# ПР №5 — разбор кода алгоритма криптоанализа простой замены

**Вариант №2 · Java**  
**Источник:** актуальная исправленная версия проекта `PR5_JavaFX_Variant2_SRP_Fixed.zip`.  
**Область разбора:** только поиск кодов, подсчёт частот, автоматические предположения, расшифровка, биграммы/триграммы, замены и их отмена. Интерфейс JavaFX, всплывающие окна и подсветка здесь не рассматриваются.

## 1. Что делает алгоритм в целом

Исходные данные — криптограмма, где **одному символу исходного текста соответствует один двузначный код**, например `39 25 20 34 82 ...`. Одна и та же буква всегда заменена одним и тем же кодом. Алгоритм:

1. Выделяет двузначные коды из криптограммы.
2. Считает, сколько раз встречается каждый код, и вычисляет относительные частоты.
3. Предлагает первоначальные соответствия «код → буква» по эталонному порядку частот русского языка.
4. Применяет таблицу замен ко всему тексту.
5. Считает частые пары/тройки кодов для проверки гипотез.
6. Позволяет вручную менять соответствия, менять их местами и отменять действия.

**Важно:** текущая программа не выполняет полноценного автоматического взлома. Автоподбор даёт **начальную гипотезу**, а осмысленность текста проверяется и уточняется вручную.

## 2. `CryptoAnalyzer`: извлечение символов — `symbols()`

```java
private static final Pattern TOKEN =
        Pattern.compile("(?<!\\d)\\d{2}(?!\\d)");

public static List<String> symbols(String raw) {
    Matcher matcher = TOKEN.matcher(raw);
    List<String> result = new ArrayList<>();
    while (matcher.find()) result.add(matcher.group());
    return result;
}
```

- `raw` — строка криптограммы вместе с пробелами и знаками препинания.
- `\\d{2}` — ровно две цифры; `(?<!\\d)` и `(?!\\d)` проверяют, что рядом нет других цифр.
- `matcher.find()` последовательно находит коды, а `matcher.group()` извлекает найденный код.
- `List<String>` сохраняет **порядок и повторения** кодов.

**Пример:** `"42 17 42, 63"` → `["42", "17", "42", "63"]`.

## 3. `CryptoAnalyzer`: подсчёт частот — `counts()`

```java
public static Map<String, Long> counts(String raw) {
    Map<String, Long> counts = new HashMap<>();
    for (String code : symbols(raw)) counts.merge(code, 1L, Long::sum);
    return counts.entrySet().stream()
            .sorted(Comparator.<Map.Entry<String,Long>>comparingLong(
                    Map.Entry::getValue).reversed()
                    .thenComparing(Map.Entry::getKey))
            .collect(Collectors.toMap(Map.Entry::getKey,
                    Map.Entry::getValue, (a,b)->a, LinkedHashMap::new));
}
```

- `HashMap<String,Long>` хранит `код → число появлений`.
- `merge(code, 1L, Long::sum)` записывает `1`, если код новый; иначе прибавляет `1` к счётчику.
- `sorted(...reversed())` сортирует по убыванию количества; при равенстве — по самому коду.
- `LinkedHashMap` сохраняет полученный порядок для отображения.

**Пример:** `42 17 42 63 17 42` → `42 = 3`, `17 = 2`, `63 = 1`.

### Откуда берётся процент частоты?

Сам `counts()` возвращает **количество**, не проценты. Процент вычисляется в методе `analyze()` класса `CryptoApp`:

```java
Map<String, Long> count = CryptoAnalyzer.counts(ciphertext.getText());
long total = count.values().stream().mapToLong(Long::longValue).sum();
// Для каждой пары (код, количество):
String frequency = String.format(
        Locale.forLanguageTag("ru"), "%.2f%%",
        100.0 * e.getValue() / total);
```

Здесь `e` — текущий элемент `count.entrySet()` в цикле (фрагмент показан для объяснения, не как самостоятельный метод).

**Формула:** `P(код) = количество_кода / общее_количество_кодов × 100%`.

Для `42`, встречающегося 3 раза из 6: `3 / 6 × 100% = 50%`.

## 4. `CryptoAnalyzer`: первоначальный автоподбор — `suggestedMappings()`

В начале класса задан порядок **наиболее частых русских символов**:

```java
public static final List<Character> FREQUENCY_ORDER = List.of(
        ' ', 'О', 'Е', 'А', 'И', 'Т', 'Н', 'С', 'Р', 'В', 'Л', 'К', 'М',
        'Д', 'П', 'У', 'Я', 'Ы', 'Ь', 'Б', 'Г', 'Ч', 'Й', 'Х', 'Ж', 'Ю',
        'Ш', 'Ц', 'Щ', 'Э', 'Ф', 'З');
```

Код метода:

```java
public static Map<String, Character> suggestedMappings(String raw) {
    return suggestedMappings(raw, true);
}

public static Map<String, Character> suggestedMappings(
        String raw, boolean includeSpace) {
    Map<String, Character> mappings = new LinkedHashMap<>();
    int i = 0;
    for (String code : counts(raw).keySet()) {
        while (i < FREQUENCY_ORDER.size()
                && !includeSpace
                && FREQUENCY_ORDER.get(i) == ' ') i++;
        if (i < FREQUENCY_ORDER.size())
            mappings.put(code, FREQUENCY_ORDER.get(i++));
    }
    return mappings;
}
```

**Логика:** отсортированные по частоте коды сопоставляются по очереди самым частым символам русского языка. При `includeSpace == false` пробел исключается из первоначального списка кандидатов; при `true` — участвует в подборе.

Для нашего варианта наиболее частые коды — `51`, `37`, `25`… В режиме **без пробела** первое предположение: `51 → О`, `37 → Е`, `25 → А`.

**Ограничение:** близость частот не доказывает правильность замены. Код не проверяет слова и не оценивает смысл текста. Порядок частот в проекте — приближение по таблице методички (для «З» частота в используемой таблице не указана).

## 5. `CryptoAnalyzer`: собственно расшифровка — `decrypt()`

```java
public static String decrypt(String raw, Map<String, Character> mappings) {
    StringBuilder output = new StringBuilder();
    Matcher m = TOKEN.matcher(raw);
    int previous = 0;
    while (m.find()) {
        String between = raw.substring(previous, m.start());
        output.append(between.replaceAll("\\s+", ""));
        Character letter = mappings.get(m.group());
        output.append(letter == null ? '·' : letter);
        previous = m.end();
    }
    output.append(raw.substring(previous).replaceAll("\\s+", ""));
    return output.toString();
}
```

1. `StringBuilder` постепенно собирает результат.
2. `Matcher` находит очередной двузначный код.
3. `substring(previous, m.start())` получает разделители перед ним; `replaceAll("\\s+", "")` удаляет **технические пробелы между кодами**, но оставляет знаки препинания.
4. `mappings.get(m.group())` ищет букву по коду.
5. Если буква не назначена — ставится `·` (маркер неизвестного символа).
6. В конце добавляется остаток строки после последнего кода.

**Пример:** `"39 25 20, 34 82 63"` с заменами `39→В`, `25→Н`, `20→А`, `34→Ш`, `82→Е`, `63→Й` → **`ВНА,ШЕЙ`**. Запятая сохраняется; пробелы-разделители между кодами исчезают.

Если какой-то **код** назначен букве `' '`, тогда соответствующий пробел попадёт в расшифровку: это уже не технический разделитель, а результат замены.

## 6. `CryptoAnalyzer`: биграммы и триграммы — `ngrams()`

```java
public static Map<String, Long> ngrams(String raw, int n) {
    List<String> codes = symbols(raw);
    Map<String, Long> count = new HashMap<>();
    for (int i = 0; i + n <= codes.size(); i++) {
        String gram = String.join(" ", codes.subList(i, i + n));
        count.merge(gram, 1L, Long::sum);
    }
    return count.entrySet().stream()
            .sorted(Comparator.<Map.Entry<String,Long>>comparingLong(
                    Map.Entry::getValue).reversed()
                    .thenComparing(Map.Entry::getKey))
            .limit(30)
            .collect(Collectors.toMap(Map.Entry::getKey,
                    Map.Entry::getValue, (a,b)->a, LinkedHashMap::new));
}
```

- `n = 2` — биграммы (пары соседних кодов); `n = 3` — триграммы.
- `subList(i, i + n)` берёт **перекрывающиеся** окна длины `n`: индекс `i` сдвигается на 1.
- `String.join(" ", ...)` формирует ключ вроде `"25 51"`.
- `merge()` считает повторения; после сортировки остаются **30 самых частых** сочетаний.

**Пример:** для `42 17 63 42 17` биграммы: `42 17`, `17 63`, `63 42`, `42 17`. Значит, `42 17` появляется **2 раза**.

**Тонкость реализации:** метод работает со всем списком кодов из `symbols()` и **не учитывает знаки препинания как границы**. Поэтому окно n-граммы может пересечь запятую или точку в исходной строке. Это особенность текущего алгоритма.

## 7. `MappingService`: ручная замена — `set()`

```java
private final Map<String, Character> mappings = new LinkedHashMap<>();
private final Deque<Map<String, Character>> history = new ArrayDeque<>();

public void set(String code, Character letter) {
    if (Objects.equals(mappings.get(code), letter)) return;
    snapshot();
    if (letter == null) mappings.remove(code);
    else {
        mappings.entrySet().removeIf(entry ->
                !entry.getKey().equals(code) && letter.equals(entry.getValue()));
        mappings.put(code, letter);
    }
}
```

Здесь `mappings` — таблица `код → буква`. Метод `set()`:

- Проверяет, отличается ли новое значение от текущего.
- Сохраняет прежнее состояние через `snapshot()`.
- Если `letter == null` — **удаляет** назначение (пустая замена).
- Если буква занята другим кодом — **снимает старое назначение**.
- Присваивает букву указанному коду.

Так обеспечивается **взаимно-однозначность**: одна буква не должна быть одновременно назначена двум кодам.

**Важно:** обычная ручная замена не обязательно меняет две буквы местами. Если буква уже занята, прежний код просто теряет её. Для обмена есть отдельный `swap()`.

## 8. `MappingService`: перестановка — `swap()`

```java
public void swap(String first, String second) {
    Character a = mappings.get(first), b = mappings.get(second);
    if (Objects.equals(a, b)) return;
    snapshot();
    if (b == null) mappings.remove(first); else mappings.put(first, b);
    if (a == null) mappings.remove(second); else mappings.put(second, a);
}
```

Пример: до — `51 → А`, `61 → Б`; после `swap("51", "61")` — `51 → Б`, `61 → А`.

Если одна замена отсутствует, метод переносит назначенную букву другому коду, а первую связь удаляет. Перед изменением записывается состояние для отмены.

## 9. `MappingService`: история и отмена — `snapshot()` / `undo()`

```java
private static final int MAX_UNDO = 100;

private void snapshot() {
    history.push(new LinkedHashMap<>(mappings));
    while (history.size() > MAX_UNDO) history.removeLast();
}

public boolean undo() {
    if (history.isEmpty()) return false;
    mappings.clear();
    mappings.putAll(history.pop());
    return true;
}
```

- `snapshot()` сохраняет **копию** таблицы перед изменением, максимум 100 состояний.
- `Deque` используется как стек: последняя сохранённая версия восстанавливается первой.
- `undo()` полностью возвращает предыдущее состояние и сообщает, удалось ли это сделать.

В `MappingService` есть также `replace(next)` (полная замена таблицы, например при автоподборе) и `clear()` (очистка); обе операции сохраняют предыдущее состояние.

## 10. Как всё связано в работе программы

Из `CryptoApp` (приведены только **вызовы алгоритма**, без кода построения JavaFX):

```java
// Подсчёт кодов:
Map<String, Long> count = CryptoAnalyzer.counts(ciphertext.getText());

// Автоподбор по режиму с пробелом / без пробела:
mappingService.replace(CryptoAnalyzer.suggestedMappings(
        ciphertext.getText(), "С пробелом".equals(analysisMode.getValue())));

// Применение текущих замен:
plaintext.setText(CryptoAnalyzer.decrypt(ciphertext.getText(), mappings));

// Ручная замена:
mappingService.set(code, letter);

// Перестановка двух выбранных кодов:
mappingService.swap(first, second);

// Отмена:
mappingService.undo();
```

Здесь `ciphertext`, `plaintext`, `analysisMode` — элементы интерфейса, а `mappings` — доступное для чтения представление карты замен из `MappingService`. После изменения замен `CryptoApp` вызывает `refresh()`, который заново расшифровывает текст и обновляет таблицу и сочетания.

## 11. Что сказать преподавателю

> В программе применяется частотный криптоанализ шифра простой замены. Сначала регулярным выражением выделяются все двузначные коды; затем с помощью `HashMap` подсчитывается число появлений каждого кода. По полученным частотам строится первоначальная гипотеза о соответствии кодов русским буквам. Далее по текущей таблице замен восстанавливается текст, а для уточнения предположений анализируются частые биграммы и триграммы. Управление соответствиями вынесено в отдельный `MappingService`, который обеспечивает уникальность замен и поддерживает перестановку и отмену изменений.

### Самое важное запомнить

| Задача | Где реализована | Ключевая идея |
|---|---|---|
| Найти коды | `CryptoAnalyzer.symbols()` | `Pattern` + `Matcher` |
| Посчитать повторы | `CryptoAnalyzer.counts()` | `HashMap` + `merge()` |
| Вычислить проценты | `CryptoApp.analyze()` | `100 × count / total` |
| Предположить буквы | `CryptoAnalyzer.suggestedMappings()` | Сопоставление рангов частот |
| Получить текст | `CryptoAnalyzer.decrypt()` | Подстановка по `Map` |
| Найти сочетания | `CryptoAnalyzer.ngrams()` | Скользящее окно длины `n` |
| Изменить букву | `MappingService.set()` | Уникальность соответствий |
| Поменять буквы местами | `MappingService.swap()` | Обмен двух значений |
| Отменить изменение | `MappingService.undo()` | Стек снимков состояния |

**Граница возможностей:** эти методы не гарантируют автоматического раскрытия текста. Они предоставляют статистику и инструмент для проверки гипотез, а окончательная расшифровка требует корректной таблицы замен.
