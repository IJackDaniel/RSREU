# Подробный разбор проекта InfSecurity Lab3

## Общая идея

Проект реализует шифр перестановки с графическим интерфейсом JavaFX + FXML.

Пользователь:

1. вводит ASCII-текст;
2. вводит ключ перестановки;
3. нажимает «Зашифровать» или «Расшифровать»;
4. получает результат.

Ключ по умолчанию соответствует варианту лабораторной работы:

```text
3 5 2 6 1 4
```

При этом пользователь может заменить его любым корректным ключом.

## Lab3Application

Пакет:

```text
application
```

Это точка входа JavaFX-приложения.

Задачи класса:

- запустить JavaFX;
- загрузить `main-view.fxml`;
- создать `Scene`;
- показать главное окно.

В нём нет логики шифрования.

## MainController

Пакет:

```text
controller
```

Связывает FXML с Java-кодом.

Он получает ссылки на:

- поле исходного текста;
- поле ключа;
- поле результата.

Обработчики кнопок:

- `onEncrypt()` - запускает шифрование;
- `onDecrypt()` - запускает дешифрование;
- `onClear()` - очищает поля;
- `onHelp()` - показывает справку.

Контроллер не переставляет символы самостоятельно. Он только вызывает сервисы.

## PermutationKey

Пакет:

```text
model
```

Класс представляет ключ перестановки как объект.

Например:

```text
3 5 2 6 1 4
```

означает:

- в результат на позицию 1 берём исходный символ 3;
- на позицию 2 - исходный символ 5;
- на позицию 3 - исходный символ 2;
- и так далее.

Метод:

```java
sourceIndexForResultIndex(...)
```

переводит человеческую нумерацию `1..n` в Java-индексы `0..n-1`.

### Обратный ключ

`inverse()` строит перестановку для дешифрования.

Если прямой ключ:

```text
3 5 2 6 1 4
```

то:

```text
Y1 = X3
Y2 = X5
Y3 = X2
Y4 = X6
Y5 = X1
Y6 = X4
```

Следовательно:

```text
X1 = Y5
X2 = Y3
X3 = Y1
X4 = Y6
X5 = Y2
X6 = Y4
```

Обратная перестановка:

```text
5 3 1 6 2 4
```

Она строится программно, поэтому не зависит от конкретного ключа.

## PermutationKeyValidator

Пакет:

```text
validator
```

Проверяет, что ключ является настоящей перестановкой.

Для ключа длины `n` должны присутствовать все числа от `1` до `n` ровно один раз.

Корректно:

```text
3 5 2 6 1 4
2 1 3
1 2 3 4
```

Некорректно:

```text
1 2 2 4
1 2 3 7
```

## KeyParserService

Пакет:

```text
service
```

Преобразует строку пользователя в объект `PermutationKey`.

Например:

```text
"3 5 2 6 1 4"
```

превращается в массив чисел, затем проходит валидацию.

Разрешены пробелы и запятые как разделители.

---

## AsciiValidator

Пакет:

```text
validator
```

Проверяет условие варианта: текст должен состоять только из стандартных ASCII-символов.

Каждый Java `char` проверяется условием:

```text
код <= 127
```

Если встретится русская буква или другой Unicode-символ, пользователь увидит ошибку.

## PermutationCipherService

Пакет:

```text
service
```

Это основной алгоритм шифрования.

### encrypt()

1. Определяет размер блока по длине ключа.
2. Если длина текста не кратна блоку - дополняет последний блок пробелами.
3. Делит текст на блоки.
4. Применяет к каждому блоку прямой ключ.

Для ключа:

```text
3 5 2 6 1 4
```

блок:

```text
ABCDEF
```

становится:

```text
CEBFAD
```

### decrypt()

1. Проверяет, что длина шифротекста кратна размеру блока.
2. Строит обратный ключ через `key.inverse()`.
3. Применяет обратную перестановку к каждому блоку.

В результате получается исходный текст вместе с возможными добавленными пробелами в конце.

### Почему пробелы автоматически не удаляются

Если безусловно делать `trim()`, программа может удалить настоящие пробелы, которые пользователь ввёл в конце исходного сообщения.

Поэтому сервис сохраняет результат без потери данных.

## HelpText

Пакет:

```text
util
```

Содержит текст справки.

Так длинный пользовательский текст не захламляет контроллер.

Справка объясняет:

FXML описывает внешний вид окна.

## Полный путь выполнения шифрования

```text
Пользователь нажимает «Зашифровать»
        ↓
MainController
        ↓
AsciiValidator
        ↓
KeyParserService
        ↓
PermutationKeyValidator
        ↓
PermutationCipherService.encrypt()
        ↓
PermutationKey
        ↓
Результат возвращается в MainController
        ↓
Показывается в resultTextArea
```

Такое разделение облегчает чтение, тестирование и защиту кода.

## Что стоит уметь объяснить преподавателю

### Почему размер блока зависит от ключа?

Потому что каждый элемент ключа указывает позицию символа внутри одного блока. Ключ из 6 чисел описывает перестановку 6 символов.

### Почему ключ нельзя задать как `1 1 2 3`?

Это не перестановка: один исходный символ используется два раза, а другой вообще теряется. Обратное преобразование стало бы невозможным.

### Почему дешифрование возможно?

Любая корректная перестановка взаимно-однозначна: каждой позиции соответствует ровно одна другая позиция. Поэтому для неё существует обратная перестановка.

### Почему используется ASCII-валидация?

Потому что по условию варианта исходный текст должен быть представлен в ASCII-коде.

### Что будет, если текст не делится на размер блока?

Последний блок дополняется пробелами до полного размера, как указано в методических материалах.
